# Алгоритмы MVP

Для MVP расчёт фиксируется так: сезонность берём из файла `Сезонность ИЭК.xlsx` как готовые месячные коэффициенты и применяем к базовому уровню спроса без повторного вывода сезонного профиля из продаж; тренд считаем объяснимым методом `rolling_window` по последнему окну спроса, а если данных мало или нужно сгладить шум, разрешён вариант `exponential_smoothing` с зафиксированным коэффициентом; выбросы определяем на уровне операций через MAD по количеству, а при наличии обезличенного `customer_id` дополнительно проверяем концентрацию крупной покупки у одного клиента и повторяемость, чтобы разовый заказ исключить, а регулярного крупного покупателя оставить; stockout компенсируем только по подтверждённым интервалам отсутствия товара через сопоставимые доступные периоды; страховой запас считаем по формуле `z * sigma(demand over lead time)`, где `z` приходит из настроек сервиса или категории, после чего заказ рассчитывается как `max(0, forecast_over_horizon + safety_stock - available_stock - eligible_inbound)` и только затем округляется по MOQ и подтверждённой кратности.

Этот абзац считается обязательным для backend-агента. Любая смена метода должна быть отражена в контракте API, fixtures и README до изменения реализации.
