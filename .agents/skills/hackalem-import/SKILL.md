# Импорт данных ИЭК

Прочитай корневые `AGENTS.md`, `PROJECT_BRIEF.md` и [карту файлов](references/iek-files.md). Это исходный профиль архива, а не гарантия неизменного формата следующей выгрузки.

## Работа

1. Проверь реальные имена листов, заголовки, диапазон дат и единицы. Читай Excel локально. Для прикладного импортера подходят Python и openpyxl/pandas; не переписывай входные книги.
2. Связывай источники по строковому коду 1С, сохраняя ведущие нули и суффиксы. Наименование не является ключом. Поставщицкий артикул храни отдельно.
3. Раздели товар, продажу/возврат, снимок остатка, ожидаемое поступление и закупочное условие. Для каждой записи сохраняй набор данных, файл, лист и строку. Денежные показатели и количества не смешивай.
4. Разверни месячные колонки в записи `товар + месяц + значение`; отбрось строки заголовков и итоги по структуре, не по случайной позиции. Для остатка сохрани смысл «на начало месяца», для продаж — полноту периода.
5. Тип документа и знак количества определяют обработку операции. До подтверждения семантики неоднозначные записи помещай в отчёт проверки; не применяй `abs()` ко всем продажам.
6. Повторный импорт того же файла не должен удваивать данные. Различай повтор загрузки, дубликат строки и законные несколько строк одного товара. Конфликтующие MOQ не разрешай молча; строки поставок не суммируй без проверки документа и единиц.
7. Отдельно сообщай о пропусках, несовпавших кодах, дублях, единицах и неизвестных датах. Не делай весь импорт успешным, если критичные строки пропали. Частичную загрузку обозначай явно.

## Недостающие сведения

Поддержи дополнительные таблицы текущих остатков, сроков поставки, категорий, интервалов stockout и обезличенных клиентов. Не изобретай их из названий файлов. Категории, предложенные по названиям товаров, помечай как предположение до подтверждения. Не выводи сроки поставки из разницы дат документа и обещанного поступления как подтверждённый справочник.

Синтетические наборы отделяй от реальных. Сохраняй флаг происхождения; не заполняй реальную базу синтетическими клиентами или остатками.

## Результат и проверка

Передай нормализованные записи, сводку качества и список неподдержанных/неподтверждённых полей. Проверь сохранность ключей, идемпотентность, разбор дат поступления, пропуск против нуля и отсутствие двойного учёта. Сверь сопоставимые месячные суммы с детализацией; расхождения объясни, а не исправляй подгонкой.
