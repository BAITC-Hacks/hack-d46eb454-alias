# Проверка MVP

Используй критерии из корневого `PROJECT_BRIEF.md`. Читай реализацию и существующие команды запуска, прежде чем выбирать проверки. Отчёт различает: проверено на реальных данных, проверено синтетически, не проверено/не реализовано.

## Значимые сценарии

| Проверка | Наблюдаемое поведение |
| --- | --- |
| Все входы | При подходящем сценарии меняются рекомендации от продаж, остатка, своевременного поступления, категории и прироста; изолируй влияние каждого входа. |
| Сезонность и рост | Прогноз повторяет контролируемый сезонный рисунок и устойчивое изменение уровня, не принимает одиночный всплеск за тренд. |
| Stockout | На одинаковом контрольном наборе с известными интервалами восстановление увеличивает оценку спроса; нет подтверждённого интервала — нет выдуманного факта. |
| Выброс | Добавленная разовая покупка выявлена и не меняет регулярный прогноз сверх численной погрешности; повторяющийся крупный клиент не исключён только по размеру. |
| Поставки | Позднее поступление не скрывает ранний дефицит; поступление за горизонтом не уменьшает текущую потребность. |
| Минимумы и единицы | Нулевая потребность не порождает MOQ-заказ; минимум, кратность и метры/бухты применяются в правильной единице. |
| Пропуски | Нет ложного нуля при неизвестном остатке/сроке; пустая история и нулевая дисперсия не ломают расчёт. |
| Импорт | Повтор загрузки не удваивает данные; нет двойного учёта детализации и агрегатов; коды сохраняются строками. |
| Заказ | Группировка, объяснения, корректировка, утверждение, снятие утверждения после изменения и экспорт проверены с сервером. |

Ожидания проверяй независимо от реализации. Для агрегатной формулы используй простой пример без MOQ: прогноз 100 + страховой запас 20 − остаток 30 − своевременное поступление 40 = заказ 50. Добавление ещё 10 своевременных единиц даёт 40. Это проверка количества, не доказательство отсутствия дефицита до прихода.

## Историческая оценка

Используй временное разделение, не случайное. На каждой отсечке все параметры обучаются только на прошлом; месяцы после отсечки и будущие остатки/поставки недоступны. Сравни прогноз с простым средним, укажи период, число товаров и метрику, устойчивую к нулевому спросу (например MAE; WAPE — только при ненулевом суммарном факте). Без истинного скрытого спроса не заявляй измеренную точность восстановления stockout или доказанное снижение дефицита.

## Ревью и сдача

Для ревью сообщай конкретный дефект, условие воспроизведения и последствие; не требуй переписывания работающего MVP ради стиля. Отдельно проверь утечку реальных данных/секретов в Git и отправку заказа без сотрудника.

Проверь запуск по README в чистом окружении, если это доступно. Иначе честно укажи, что проверен только текущий компьютер. Зафиксируй использованные команды и результаты, открытые ограничения данных и готовность каждого из пяти требований. Не отмечай «пройдено» по наличию кода или теста без его запуска.
