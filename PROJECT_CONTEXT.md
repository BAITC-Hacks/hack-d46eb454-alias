# Текущие решения

## Пагинация интерфейса

В «Закупках» и позициях выбранного заказа — по 20 строк, с выбором 10/20/50 и навигацией сверху/снизу. Поиск/фильтры применяются ко всему результату до пагинации. Смена фильтра или нового расчёта сбрасывает страницу; сохранение строки заказа не сбрасывает. При несохранённых правках переход страницы запрещён, чтобы не потерять локальный ввод. Пагинация клиентская, API и область утверждения/экспорта не меняются.

Обновлено 23.09.2026. Требование пользователя: основной рабочий вход — шесть таблиц `ф1.xlsx`–`ф6.xlsx`; дополнительные выгрузки сейчас не обязательны для получения результата. Пример и восстановление демонстрационного расчёта удалены из пользовательского интерфейса; тестовые fixtures остаются для регрессий разработчика.

## Прогноз отдельно от заказа

Ранее отсутствие текущего остатка исключало товар из расчёта целиком. Теперь история продаж даёт прогноз спроса, очистку аномалий, сезонность/тренд и страховой запас независимо от наличия остатка. При неизвестном остатке количество заказа, чистая потребность и дата дефицита неизвестны, а не равны нулю.

Для шести таблиц доступен отдельный, выключенный по умолчанию режим предварительного плана: `max(0, остаток на начало месяца − положительные продажи с начала месяца до даты расчёта)`. Применяется только явно выбранный `stock_mode=monthly_estimate`, только снимок того же месяца и с совпадающей единицей. Включение означает пользовательское принятие допущения об охвате склада и отсутствии неучтённых движений. Если подходящего снимка нет, остаётся прогноз без количества заказа. Это не восстановленный факт: поступления, возвраты, резервы и перемещения неизвестны. Фактический снимок всегда приоритетнее оценки.

API дополнен `stock_mode`, `components.stock_estimate`; `recommended_quantity`, `calculated_quantity`, `net_need_before_rounding`, `rounding_delta` могут быть null; `urgency=unknown` для прогноза без запаса. Для оценки `available_stock` остаётся null, значение оценки и её источник хранятся отдельно. Версия алгоритма v0.2. Сервер не позволяет утверждать/экспортировать прогноз или оценочный план как фактический заказ, в том числе после ручной правки.

Сырые файлы и рассчитанные данные остаются локально. Не гарантирована точность прогноза или оценки остатка на реальном бизнесе; вычислительная работоспособность и честное обозначение ограничений не равны бизнес-валидации.
