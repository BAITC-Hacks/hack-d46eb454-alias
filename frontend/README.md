# EKT — интерфейс закупщика

React + TypeScript + Vite интерфейс работает с локальным FastAPI. Согласованный контракт — `../contracts/openapi.yaml`; перевод ответа сервера в модели экранов находится в `src/api/mapper.ts`. Исходные данные партнёра и рабочая база остаются локально вне Git.

## Запуск

Из корня репозитория запустите сервер:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173/#/data`. Прокси Vite направляет `/api` на локальный сервер. При другом адресе сервера используйте `API_PROXY_TARGET` из `.env.example`.

Проверки из `frontend/`:

```bash
npm run build
npm test
npm run test:e2e
```

Playwright запускает FastAPI и Vite при наличии `.venv` в корне. Для проверки реальных шести XLSX задайте `IEK_FILES_DIR=/абсолютный/путь/IEK`, где находятся `ф1.xlsx`–`ф6.xlsx`; эти файлы не копируются в репозиторий. Если Chrome отсутствует, установите Chromium и запустите с `PLAYWRIGHT_CHANNEL=chromium`.

## Docker Compose

Из корня репозитория:

```bash
docker compose up --build
```

Интерфейс: `http://127.0.0.1:8080/#/data`. API и Swagger: `http://127.0.0.1:8000/docs`.

Compose запускает frontend и FastAPI, а Nginx проксирует `/api` на backend. Снимки импорта и SQLite сохраняются в Docker volume `hackalem_data`, поэтому не исчезают после перезапуска контейнеров. Остановить сервисы: `docker compose down`. Полностью удалить локальные данные: `docker compose down --volumes`.

## Рабочий путь

1. На экране «Данные» выберите `.xlsx` или архив `.zip`, задайте склад и нажмите «Проверить файлы». `POST /api/import/preview` объединяет источники; интерфейс пока показывает только файлы и количества строк. Поддерживаются раздельные файлы, листы и общая таблица: [форматы](../docs/import-formats.md).
2. Задайте дату расчёта, срок поставки, период пересмотра, коэффициент `z` и плановый прирост. «Сохранить набор и рассчитать» вызывает `POST /api/import/commit`, затем `POST /api/recommendations/calculate` с выданным `dataset_id`. Результат и замечания появляются только на «Данных». При переходе в другие разделы отчёт скрыт, при возвращении доступен, после обновления страницы исчезает. В «Закупки» переходят отдельной кнопкой «Посмотреть рекомендации».
3. На экране «Закупки» результаты поиска и фильтров берутся из одного ответа `RecommendationRun`; дополнительного опроса сервера и серверной пагинации нет. При перезагрузке приложение запрашивает сохранённый `run_id` через `GET /api/recommendations/runs/{run_id}`.
4. На экране «Заказы» поставщики — разделы одного расчёта. Правка количества с причиной вызывает `PATCH /api/recommendations/runs/{run_id}/items/{item_id}/adjust`. Подтверждение относится ко всему run и вызывает `POST /api/orders/{run_id}/approve`. CSV и XLSX скачиваются с сервера после утверждения.

Таблица «Закупки» и позиции выбранного заказа имеют клиентскую пагинацию: 20 строк по умолчанию, выбор 10/20/50, навигация сверху и снизу. Фильтрация выполняется до разбивки на страницы. После смены фильтров, расчёта или размера страницы выбирается первая страница. Несохранённые правки блокируют пагинацию заказа; после сохранения текущая страница сохраняется. Экспорт/утверждение по-прежнему относятся ко всему серверному расчёту.

Синтетический пример удалён из интерфейса; ранее сохранённый демо-run больше не восстанавливается. Тестовые fixtures доступны только разработчику для регрессий. В интерфейсе оставлены три рабочих раздела: «Данные», «Закупки» и «Заказы». Итоговый CSV/XLSX формирует сервер только после подтверждения фактического заказа.

Шесть таблиц ИЭК дают прогноз спроса даже без текущего остатка: в «Закупках» есть отдельная колонка прогноза, неизвестное количество заказа не отображается нулём. Для предварительного количества можно явно включить «Предварительный план по оценке месячного остатка». Формула и допущения показаны рядом с опцией, оценка отмечается в каждой строке и карточке. Это не фактический заказ; сервер и интерфейс блокируют его утверждение. После перезагрузки исчезает только экранный отчёт: сохранённый реальный набор и расчёт остаются.

## Известные границы контракта

- В согласованной схеме `ImportPreviewResponse` отсутствует `preview_id`, хотя `CommitImportRequest` его требует. Текущий backend добавляет `preview_id` в фактический ответ; контракт должен быть дополнен интегратором после согласования.
- Сервер не передаёт цены, валюту, отдельное утверждение поставщика или временной ряд спроса. UI не выводит денежные суммы и не создаёт эти данные.
- Экспорт CSV/XLSX проверен через API, но формат не объявлен совместимым с конкретной конфигурацией 1С без её образца.
- Docker Compose рассчитан на локальную демонстрацию. Архивы IEK и другие реальные данные загружаются через экран «Данные» и не включаются в образ.
